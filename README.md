# brood

brood — самостоятельно разворачиваемый сервер, который запускает агентов
программирования (Claude Code) в отдельных LXC-контейнерах Proxmox VE. Человек
и агенты переписываются друг с другом из командной строки, веб-панели и
Telegram.

Проект в разработке, выпусков нет. Подробнее — в разделе [Состояние](#состояние).

## Понятия

- **Проект** — окружение для работы: имя, участники, Git-репозиторий и доступ
  к нему, лимиты, секреты и образы агентов.
- **Рой** — группа агентов внутри проекта и область, в которой они обмениваются
  сообщениями. У роя один владелец; доступ к рою есть у владельца и
  у администратора.
- **Агент** — один контейнер Proxmox с сессией Claude Code, рабочей копией
  репозитория и терминалом. Роль агента — обычный агент или мастер; мастер
  может создавать других агентов и управлять теми, кого создал.
- **Пул** — подключение к Proxmox VE и бюджет ресурсов (агенты, процессор,
  память, диск), который делится между агентами поровну. Пулы заводит
  администратор.
- **Образ** — шаблон контейнера, собранный для проекта из его плейбука
  `brood.yaml`. Новые агенты проекта — клоны последнего готового образа.

Полное описание — [docs/MODEL.md](docs/MODEL.md).

## Как это устроено

```text
  человек: bro / веб-панель / Telegram
                  |
                  v
  +-------------------------------+
  |  сервер brood                 |
  |  SQLite, панель, шлюз моделей |
  +-------------------------------+
     |  Proxmox API,        ^
     |  SSH при установке   |  исходящее соединение
     v                      |  агента (WebSocket)
  +-------------------------------+
  |  Proxmox VE                   |
  |  контейнер = агент:           |
  |  brood-guest, Claude Code,    |
  |  терминал, /workspace         |
  +-------------------------------+
```

Сервер — один Go-бинарник `brood` с базой SQLite и встроенной панелью. Клиент —
бинарник `bro`. В каждом контейнере работает `brood-guest`: он держит сессию
Claude Code, отдаёт терминал и сам подключается к серверу, поэтому серверу не
нужен входящий доступ к контейнерам после установки агента.

## Что нужно

- Proxmox VE с API-токеном для brood и шаблоном Debian для LXC
  ([docs/PROXMOX.md](docs/PROXMOX.md)).
- Машина для сервера, доступная агентам по HTTPS
  ([docs/DEPLOY.md](docs/DEPLOY.md)).
- Учётные данные поставщика моделей для встроенного CLIProxyAPI. Шлюз
  работает в процессе `brood`; управлять им можно из панели
  ([docs/GATEWAY.md](docs/GATEWAY.md)).

## Быстрый старт

Сервер уже развёрнут, у вас есть учётная запись.

1. Войдите:

   ```sh
   bro login brood.example.com
   ```

2. Администратор подключает Proxmox и создаёт пул в панели, раздел «Пулы».
   Проверить можно командой `bro pools` (она доступна администратору).

3. В корне репозитория проекта создайте `brood.yaml` — плейбук Ansible,
   который описывает проект и ставит в образ то, что нужно агенту для работы:

   ```yaml
   - name: agent image
     hosts: localhost
     connection: local
     gather_facts: false

     vars:
       brood:
         project: my-project
         description: My project

     tasks:
       - name: Developer packages
         ansible.builtin.apt:
           name: [build-essential, git, make]
           state: present
           update_cache: true
   ```

4. Закоммитьте и отправьте файл, затем объявите проект и соберите образ.
   Сервер собирает образ из коммита в репозитории, а не из рабочего каталога:

   ```sh
   bro build
   ```

   Первый запуск создаёт проект, поэтому его выполняет администратор.

5. Создайте рой и агента:

   ```sh
   bro swarm add main
   bro add
   ```

   `bro add` ждёт, пока агент заработает, и называет его `agent-1`.

6. Работайте с агентом:

   ```sh
   bro attach agent-1                        # консоль агента, Ctrl-] — выйти
   bro send agent-1 run the tests and report # сообщение в сессию агента
   bro tail agent-1                          # последние строки его экрана
   ```

Все команды — в [docs/CLI.md](docs/CLI.md).

## Разработка

Сервер и клиент — Go-модуль в `go/`; версия Go закреплена в `go/go.mod`.

```sh
make -C go build      # go/bin/brood и go/bin/bro
```

Панель — React-приложение в `web/`. Она собирается Bun в один файл, который
встроен в бинарник сервера; для обычной сборки Go Bun не нужен. Подробности —
[docs/GO.md](docs/GO.md) и [docs/WEB.md](docs/WEB.md).

Каталог `brood/` и `bin/brood` — инструменты разработчика на Python (трекер,
CI, выкладка). В продукт они не входят.

## Состояние

- Проект в разработке, выпусков нет. Интерфейсы меняются без обратной
  совместимости.
- Миграций схемы нет: сервер отказывается работать с базой другой версии
  схемы, базу создают заново.
- Сервер работает как `brood.service` под systemd, без Kubernetes и Docker.
  GitLab CI выкладывает его через ограниченную SSH-команду
  ([docs/DEPLOY.md](docs/DEPLOY.md)).
- В `brood-guest` остаётся неиспользуемый код удалённого движка workflow.
- На время текущей перестройки тесты не поддерживаются.
- Сеть агента не ограничивается.
