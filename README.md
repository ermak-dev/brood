# brood

brood запускает агентов Claude Code в отдельных LXC-контейнерах Proxmox VE. У каждого агента свой терминал и рабочая копия проекта. Отправлять задания и читать ответы можно из веб-панели, командной строки или Telegram.

## Установка из исходников

Инструкция рассчитана на новую машину с Debian amd64 и systemd. На ней будет работать **сервер brood** с веб-панелью и базой SQLite. **Узел Proxmox VE** понадобится позже, когда вы будете создавать агентов. Для сборки и первого входа в панель подключать его не нужно.

### 1. Подготовьте машину для сервера

- Назначьте серверу DNS-имя, например `brood.example.com`. Оно должно открываться и с вашего компьютера, и из будущих контейнеров агентов.
- Подготовьте TLS-сертификат для этого имени (PEM с цепочкой сертификатов) и соответствующий закрытый ключ без пароля. Откройте входящий TCP-порт 443. Для встроенного шлюза моделей оставьте свободным `127.0.0.1:8317`; снаружи этот порт открывать не надо.
- Установите инструменты сборки и [Go для Linux amd64](https://go.dev/doc/install) версии **1.27.0 или новее** (минимум указан в [go/go.mod](go/go.mod)):

```sh
sudo apt update
sudo apt install git make curl ca-certificates openssl python3
go version
```

### 2. Скачайте исходники и соберите brood

На странице репозитория нажмите **Code → HTTPS** и скопируйте адрес. На сервере выполните команды от обычного пользователя, заменив `URL_РЕПОЗИТОРИЯ` скопированным адресом:

```sh
git clone URL_РЕПОЗИТОРИЯ brood
cd brood
bash deploy/build-local.sh
```

Скрипт собирает сервер `go/bin/brood`, клиент `go/bin/bro` и программу для контейнеров. Он также скачивает закреплённую версию Claude Code, сверяет SHA-256 и готовит каталог `go/bin/artifacts`, из которого агенты получат свои программы. Для этого шага нужен интернет. Панель уже включена в исходники в собранном виде.

### 3. Установите и запустите службу

Из того же каталога запустите установщик. **Замените все три аргумента своими значениями**: имя сервера без `https://`, путь к сертификату и путь к ключу.

```sh
sudo bash deploy/install-local.sh brood.example.com /path/to/fullchain.pem /path/to/privkey.pem
```

Установщик создаст системного пользователя `brood`, поместит файлы сервера в `/var/lib/brood`, а клиент `bro` в `/usr/local/bin`. Он сам сгенерирует секреты, настроит встроенный шлюз моделей и включит автозапуск `brood.service`. В конце он дождётся ответа сервера по HTTPS. Это **первая установка**, не команда обновления: существующую установку скрипт не заменяет.

Проверьте доступ со своего компьютера (подставьте своё DNS-имя):

```sh
curl https://brood.example.com/healthz
```

Ожидаемый ответ — `ok`. Если ответа нет, проверьте DNS, сертификат и доступность порта 443. Журнал на сервере: `sudo journalctl -u brood.service -n 50 --no-pager`.

### 4. Создайте администратора и войдите в панель

На сервере выполните команду и введите имя и пароль первого администратора:

```sh
sudo -u brood env BROOD_DB_PATH=/var/lib/brood/brood.db /var/lib/brood/brood bootstrap-admin
```

Откройте `https://brood.example.com` под своим DNS-именем и войдите с этими данными. Для работы агентов добавьте в панели учётные данные поставщика моделей. Ключи, созданные установщиком, защищают сам шлюз, но не дают доступа к моделям. Подробнее — в [руководстве по шлюзу](docs/GATEWAY.md).

### 5. Подключите Proxmox для запуска агентов

1. **На узле Proxmox** загрузите базовый LXC-шаблон Debian 13 amd64. Выберите хранилище для дисков контейнеров и сетевой мост с DHCP. Создайте ресурсный пул, сервисного пользователя и API-токен. [Команды подготовки узла](docs/PROXMOX.md#подготовка-узла) описывают права и получение SHA-256 шаблона. Сохраните секрет токена: Proxmox покажет его только один раз.
2. **Проверьте сеть:** серверу brood нужен доступ к HTTPS API узла и по SSH (TCP 22) к контейнерам при установке. Контейнеры должны видеть сервер brood по его HTTPS-имени.
3. **В панели brood** откройте «Пулы». Укажите адрес API, сертификат центра сертификации (CA), токен, узел, имя уже созданного ресурсного пула, мост, хранилище, шаблон и его SHA-256. Задайте лимиты ресурсов и активируйте пул. В панели пул должен отображаться включённым. Не удаляйте пул ресурсов и архив шаблона в Proxmox, пока brood их использует.

## Первый агент

Команды ниже выполняются там, где лежит рабочая копия **вашего проекта**. Можно работать прямо на сервере: клиент `bro` уже установлен. Для другой машины той же архитектуры скопируйте туда `go/bin/bro` в каталог из `PATH`.

1. Войдите под созданным администратором и убедитесь, что пул включён:

   ```sh
   bro login brood.example.com
   bro pools
   ```

   Если сертификат выпущен вашим собственным центром сертификации, используйте `bro login brood.example.com --ca ca.pem`.

2. В корне репозитория проекта создайте файл `brood.yaml`. Это плейбук Ansible: `vars.brood.project` задаёт имя проекта, а `tasks` устанавливает пакеты в образ будущих агентов.

   ```yaml
   - name: agent image
     hosts: localhost
     connection: local
     gather_facts: false
     vars:
       brood:
         project: my-project
         description: My project
     tasks:
       - name: Developer packages
         ansible.builtin.apt:
           name: [build-essential, git, make]
           state: present
           update_cache: true
   ```

3. Соберите образ. При первом запуске `bro build` создаст проект, поэтому эту команду выполняет администратор. Сборка берёт файлы из текущей рабочей копии, включая незакоммиченные изменения.

   ```sh
   bro build
   ```

4. Создайте рой (группу агентов проекта) и первого агента. `bro add` создаст контейнер из образа и дождётся запуска `agent-1`.

   ```sh
   bro swarm add main
   bro add
   ```

5. Отправьте задание и посмотрите ответ. Чтобы открыть терминал агента, выполните `bro attach agent-1`; для выхода нажмите `Ctrl-]`.

   ```sh
   bro send agent-1 describe this project
   bro tail agent-1
   ```

## Обслуживание

- Настройки службы лежат в `/var/lib/brood/.env`. После изменения настроек перезапустите службу: `sudo systemctl restart brood.service`.
- Установщик **копирует** сертификат и ключ в `/var/lib/brood/tls.crt` и `/var/lib/brood/tls.key`. При продлении замените обе копии, сохранив владельца `brood` и права `0600`, и перезапустите службу.
- Храните закрытую резервную копию каталога `/var/lib/brood`: в нём база, SSH-ключ установки, ключ TLS и данные шлюза. Для согласованной файловой копии сначала остановите службу, после копирования запустите её снова.
- Проект в разработке, стабильных выпусков пока нет. Если новая версия меняет схему базы, автоматической миграции нет. Сеть контейнеров агента по умолчанию не изолирована от доступных ему адресов.
