# brood — Code Guidelines

brood — пул агентов на Agent Substrate. Мастер раздаёт работу акторам;
трекер, CI и диспетчер живут в этом репозитории. **MUST**-правила оплачены
отладкой; **SHOULD** — настоятельно рекомендованы.

Этот файл держит только то, чего репозиторий не расскажет сам: структура —
из `ls`, команды — из `brood` без аргументов, причина решения — из комментария
рядом с кодом, подсистемы — из `docs/`: по одному файлу на подсистему,
UPPERCASE-именем.

Процесс разработки совместим с Agent Substrate (`AGENTS.md` апстрима):
один PR — одно изменение, squash-merge, короткие прямые сообщения коммитов
без заголовков и эм-дэшей, American English в коде и коммитах, тесты
`go test -race ./...` и линтеры зелёные перед ревью. Русский остаётся
языком трекера: заголовки и тела задач — по-русски, ветки и коммиты —
по-английски.

## Структура

 - `cmd/brood` — единая точка входа: диспетчер командлетов. Ничто не
   запускается в обход него
 - `internal/gitlab` — клиент GitLab API и чистая логика трекера/CI:
   возвращает данные, ничего не печатает
 - `internal/cli/dev` — командлеты разработчика: bug (трекер), ci (пайплайны)
 - `docs/` — по одному файлу на подсистему, UPPERCASE-слово
 - `.env` — секреты установки; в git не попадает, как `inventory.yaml`

## Правила

 - **MUST** Всё через `brood <подкоманда>`: диспетчер — единственный вход.
   Новая возможность — новый командлет, а не обход сбоку
 - **MUST** Библиотека возвращает данные и молчит; печатают только
   командлеты — иначе второй фронтенд начнёт парсить текст, разложенный
   для терминала
 - **MUST** Вывод — английский: его читает модель, не только человек.
   Комментарии и докстринги — русский
 - **MUST** Командлеты не зовут друг друга подпроцессом: каждый разбирает
   свои аргументы и печатает сам
 - **MUST** Координаты трекера — из git origin рабочей копии, а не из
   настройки: проект в трекере и проект в git — один проект. `.env`
   переопределяет (`GITLAB_SITE`, `GITLAB_PROJECT`)
 - **MUST** Секрет один: `GITLAB_TOKEN` в `.env`; в код, настройки на узлы
   и вывод он не попадает
 - **MUST** Отказ несёт причину тому, кто его читает (CLI, модель):
   строкой, не трассировкой
 - **MUST** Метка — из словаря, ровно одна из каждой группы: вторая той же
   группы молча вытесняет первую. Опечатка заводит новую метку — отказ с
   перечнем значений
 - **MUST** Комментарий `#123` в теме коммита, без закрывающих слов:
   GitHub/GitLab рисуют перекрёстные ссылки на каждом force-push
 - **MUST NOT** Командлеты пространства `dev` не пишутся на Go — Go это
   ядро; dev-командлеты — Go, shell или python на выбор (см. «Процесс»)
 - **MUST NOT** Никаких emoji; никаких КАПС кроме идентификаторов, статусов
   (`FAILED`) и MUST/SHOULD этого файла

## Процесс (в духе mop, совместимый с substrate)

 - Одна задача = один issue, до кода. Форма: шаги воспроизведения,
   ожидание, факт, доказательство, причина (когда подтверждена), что делать
 - Перед новой задачей — поиск дубля (`brood dev bug list --all -t ...`)
 - Ветка задачи: `[type]/[iid]-[slug]`, от свежей main
 - Один фикс = один слой: обёртка, библиотека и командлет меняются
   отдельными PR
 - Строгий TDD для чистых функций (слаг, таблицы, вердикты пайплайна):
   сначала падающий тест в пакете рядом, потом минимальная правка. Никогда
   не ослаблять тест ради зелёного
 - Go: `gofmt`, короткие функции, зависимости через конструкторы, никаких
   глобалов ради тестов
 - Перед PR: `go test -race ./...`, `go vet ./...`, ревью собственного
   диффа; для существенных — свежая агент-сессия ревьюит его адверсариально
 - Landing: rebase на main, один push; ревью комментариев — отдельный push
   без rebase, чтобы ревьюер видел, что поменялось

## Ловушки (каждая оплачена отладкой)

 - `.env` в mop хранит значения в кавычках (`GITLAB_SITE='git.ermak.dev'`)
   — парсер снимает кавычки, а не режет значение по первому `=`
 - Трасса джобы — сырой текст с `\r` секций: без `screenLines` хвост лога —
   мусор маркеров
 - «Закрытая parked» пропадает из списков и выглядит сделанной: открытые
   статусы — live, wip, parked
 - GitLab принимает отмену законченного пайплайна и молча ничего не делает:
   отказ с именем состояния — до запроса
 - Идущий пайплайн с проваленной джобой вне deploy-стадии — это провал,
   а не «жди»: вердикт смотрит джобы, не только статус пайплайна
 - `origin/HEAD` выставлен не в каждом клоне: откат на master, а не отказ
   завести ветку
 - Тело задачи пустым быть не может; перенос строк и бэктики едут
   `--body-file` или stdin, не аргументом

## Словарь

 - **Актор** — единица работы на Agent Substrate; **пул** — воркеры,
   на которых акторы живут. Папет в терминах mop = актор в brood
 - **Трекер** — GitLab issues; **интеграционная ветка** — main
 - Комментарий в теме коммита — голый `#74`, никогда `Fixes #74`
