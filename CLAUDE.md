# brood — Code Guidelines

brood — пул агентов на Agent Substrate. Мастер раздаёт работу акторам;
трекер, CI и диспетчер живут в этом репозитории. **MUST**-правила оплачены
отладкой; **SHOULD** — настоятельно рекомендованы.

Этот файл держит только то, чего репозиторий не расскажет сам: структура —
из `ls`, команды — из `brood` без аргументов, причина решения — из комментария
рядом с кодом, подсистемы — из `docs/`: по одному файлу на подсистему,
UPPERCASE-именем.

Процесс разработки совместим с Agent Substrate (`AGENTS.md` апстрима):
один PR — одно изменение, squash-merge, короткие прямые сообщения коммитов
без заголовков и эм-дэшей, American English в коде и коммитах, тесты
`brood server test` и `ruff check` зелёные перед ревью. Русский остаётся
языком трекера: заголовки и тела задач — по-русски, ветки и коммиты —
по-английски.

## Структура

Код разделён на четыре модуля по дистрибутивам, пятого нет:

 - `brood/common` — общее всем: настройки установки (`.env`), таблицы,
   диспетчер командлетов (`brood/common/cli`)
 - `brood/client` — машина оператора и шелл мастера
 - `brood/server` — сервер установки: проект Django (`settings.py`,
   `urls.py`, `manage.py`), приложения — подпакетами рядом
 - `brood/dev` — инструменты разработчика: venv рабочей копии, трекер и CI
   (`brood/dev/gitlab.py`), командлеты `brood dev` (`brood/dev/cli`),
   локальный Substrate в kind (`brood/dev/substrate`, `brood substrate`).
   В дистрибутивы не едет
 - `brood/<модуль>/tests/` — проверки модуля по конвенции Django;
   `brood/common/tests/test_layout.py` держит границы модулей
 - `bin/brood` — единственный исполняемый файл: выбирает дерево, активирует
   его `venv/` и зовёт диспетчер. Ничто не запускается в обход него
 - `pyproject.toml` — зависимости extra-группами по модулям (`server`, `dev`)
 - `.ci/` — шаги пайплайна скриптами, `.gitlab-ci.yml` их только зовёт;
   `deploy/` — машина деплоя и принудительная команда выкладки
   (`docs/DEPLOY.md`)
 - `docs/` — по одному файлу на подсистему, UPPERCASE-слово
 - `.env` — секреты установки; в git не попадает, как `inventory.yaml`,
   `venv/` и `db.sqlite3`

## Правила

 - **MUST** Код — Python 3.12+, Go не пишем. Фичи mop переносятся по
   частям с его устройством: командлет — модуль, группа — подпакет,
   докстринг модуля — справка
 - **MUST** Весь код лежит в одном из модулей `common`, `client`, `server`,
   `dev`: дистрибутив собирается каталогами, без вырезания. Импорт — только
   внутри своего дистрибутива: `common` берёт stdlib и `common`; `client`,
   `server` и `dev` берут `common` и себя. `client` и `server` не знают
   друг о друге и о `dev`. Нужное двум модулям переезжает в `common`, а не
   импортируется у соседа. `common` не тянет сторонних библиотек: он едет
   в каждый дистрибутив. Относительных импортов нет: их не видит проверка
   границ в `brood/common/tests/test_layout.py`
 - **MUST** Командлеты модуля живут в его пакете `cli`:
   `brood/dev/cli/bug/list.py` → `brood dev bug list`. Пространство команд,
   не названное модулем, — пакет `cli` подпакета модуля:
   `brood/dev/substrate/cli/start.py` → `brood substrate start`; код
   остаётся в модуле своего дистрибутива. Одно имя группы в двух местах —
   отказ диспетчера. Диспетчер находит их обходом каталогов, а не импортом
   по имени, поэтому дистрибутив без модуля просто не видит его команд
 - **MUST** Сервер — Django, и `brood server <команда>` — его `manage.py`.
   Новая команда сервера — management command приложения
   (`<app>/management/commands/`), а не модуль в `brood/server/cli`
 - **MUST** Тесты — по конвенции Django: в пакете `tests/` модуля или
   приложения, на `unittest` (`django.test` — только в `server`). Гоняет
   их `brood server test`: без меток — весь пакет brood из любого каталога
 - **MUST** Окружение — `venv/` рабочей копии: его заводит `brood dev setup`
   из extras `pyproject.toml`, `bin/brood` активирует. Зависимость
   объявляется extra своего модуля, не ставится руками
 - **MUST** Всё через `brood <подкоманда>`: диспетчер — единственный вход.
   Новая возможность — новый командлет, а не обход сбоку
 - **MUST** Библиотека возвращает данные и молчит; печатают только
   командлеты (пакеты `cli`) — иначе второй фронтенд начнёт парсить текст,
   разложенный для терминала
 - **MUST** Вывод — английский: его читает модель, не только человек.
   Комментарии и докстринги — русский; докстринг модуля командлета — его
   справка, он английский
 - **MUST** Командлеты не зовут друг друга подпроцессом: каждый разбирает
   свои аргументы и печатает сам
 - **MUST** Координаты трекера — из git origin рабочей копии, а не из
   настройки: проект в трекере и проект в git — один проект. `.env`
   переопределяет (`GITLAB_SITE`, `GITLAB_PROJECT`)
 - **MUST** Свойство машины (путь, адрес) — настройка `.env` без дефолта в
   коде: `SUBSTRATE_SOURCE`, клон substrate разработчика. Зашитый дефолт
   отдаёт машину автора; отказ называет настройку. Каталог данных brood —
   `$XDG_DATA_HOME/brood`, свойство пользователя, а не машины автора
 - **MUST** Секреты — только в `.env`: `GITLAB_TOKEN` и
   `DJANGO_SECRET_KEY`; в код, настройки на узлы и вывод они не попадают.
   Секреты выкладки — защищённые переменные CI (`BROOD_DEPLOY_*`), в
   репозитории нет ни адреса машины деплоя, ни ключа
 - **MUST** Ключ выкладки умеет одно: в `authorized_keys` машины деплоя у него
   `restrict,from=<builder>,command=brood-deploy`. Новое действие на машине —
   правка `deploy/brood-deploy.sh`, а не второй ключ или шелл
 - **MUST** Отказ несёт причину тому, кто его читает (CLI, модель):
   строкой, не трассировкой
 - **MUST** Метка — из словаря, ровно одна из каждой группы: вторая той же
   группы молча вытесняет первую. Опечатка заводит новую метку — отказ с
   перечнем значений
 - **MUST** Комментарий `#123` в теме коммита, без закрывающих слов:
   GitHub/GitLab рисуют перекрёстные ссылки на каждом force-push
 - **MUST NOT** Никаких emoji; никаких КАПС кроме идентификаторов, статусов
   (`FAILED`) и MUST/SHOULD этого файла

## Процесс (в духе mop, совместимый с substrate)

 - Одна задача = один issue, до кода. Форма: шаги воспроизведения,
   ожидание, факт, доказательство, причина (когда подтверждена), что делать
 - Перед новой задачей — поиск дубля (`brood dev bug list --all -t ...`)
 - Ветка задачи: `[type]/[iid]-[slug]`, от свежей main
 - Один фикс = один слой: обёртка, библиотека и командлет меняются
   отдельными PR
 - Строгий TDD для чистых функций (слаг, таблицы, вердикты пайплайна):
   сначала падающий тест в `brood/<модуль>/tests`, потом минимальная
   правка. Никогда не ослаблять тест ради зелёного
 - Python: короткие функции, зависимости через аргументы и конструкторы,
   никаких глобалов ради тестов
 - Перед PR: `brood server test`, `ruff check`, ревью собственного диффа;
   для существенных — свежая агент-сессия ревьюит его адверсариально
 - Landing: rebase на main, один push; ревью комментариев — отдельный push
   без rebase, чтобы ревьюер видел, что поменялось

## Ловушки (каждая оплачена отладкой)

 - Имена контейнеров локального Substrate постоянные
   (`substrate-control-plane`, `substrate-registry`): каждая команда
   `brood substrate` сверяет метки и Id с записями владения до первой
   правки, иначе остановит или удалит чужой кластер
 - Envoy Substrate не поднимается без IPv6 в ядре Docker даже в кластере
   IPv4: `ipv6.disable=1` — отказ до раскатки, хост не трогаем

 - `.env` в mop хранит значения в кавычках (`GITLAB_SITE='git.ermak.dev'`)
   — парсер снимает кавычки, а не режет значение по первому `=`
 - Трасса джобы — сырой текст с `\r` секций: без `screen_lines` хвост лога —
   мусор маркеров
 - «Закрытая parked» пропадает из списков и выглядит сделанной: открытые
   статусы — live, wip, parked
 - GitLab принимает отмену законченного пайплайна и молча ничего не делает:
   отказ с именем состояния — до запроса
 - Идущий пайплайн с проваленной джобой вне deploy-стадии — это провал,
   а не «жди»: вердикт смотрит джобы, не только статус пайплайна
 - `origin/HEAD` выставлен не в каждом клоне: откат на `origin/main`, а не
   отказ завести ветку
 - Тело задачи пустым быть не может; перенос строк и бэктики едут
   `--body-file` или stdin, не аргументом

## Словарь

 - **Актор** — единица работы на Agent Substrate; **пул** — воркеры,
   на которых акторы живут. Папет в терминах mop = актор в brood
 - **Трекер** — GitLab issues; **интеграционная ветка** — main
 - Комментарий в теме коммита — голый `#74`, никогда `Fixes #74`
