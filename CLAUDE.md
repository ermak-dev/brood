# brood — Code Guidelines

brood запускает агентов (Claude Code) в отдельных LXC-контейнерах Proxmox VE
и связывает их с человеком и друг с другом. Сервер, клиент, агент в
контейнере, панель и инструменты разработки живут в этом репозитории.
**MUST**-правила оплачены отладкой; **SHOULD** — настоятельно рекомендованы.

Этот файл держит только то, чего репозиторий не расскажет сам: структура —
из `ls`, команды — из `bro help` и `brood` без аргументов, причина решения —
из комментария рядом с кодом, подсистемы — из `docs/`: по одному файлу на
подсистему, UPPERCASE-именем.

Один PR — одно изменение, squash-merge, короткие прямые сообщения коммитов
без заголовков и эм-дэшей, American English в коде и коммитах. Русский
остаётся языком документации и трекера: заголовки и тела задач — по-русски,
ветки и коммиты — по-английски.

## Временный режим (с 2026-11-20, до отмены оператором)

Оператор временно отменил проверки ради скорости. Пока этот раздел есть,
он важнее правил ниже о тестах, ревью и процессе:

 - Тесты не пишутся и не запускаются: ни `brood dev test`, ни `go test`,
   ни `brood dev web test`, ни `ruff check`. Строгий TDD и адверсариальное
   ревью не нужны. В CI проверки — ручные джобы, выкладку они не держат
 - Работа локальная: без push, MR, CI и выкладки, пока оператор не попросит
 - Каждая задача садится коммитом прямо в main, без ветки задачи и rebase
 - Миграции схемы не пишутся: при изменении схемы БД удаляется и создаётся
   заново. Данные старой базы не сохраняются
 - Стенд выкладывается в `BROOD_DEPLOY_MODE=fixture`: каждый релиз
   пересоздаёт базу, администратор и его Telegram-бот приходят из фикстуры
   (защищённая CI-переменная `BROOD_DEPLOY_FIXTURE`, `docs/DEPLOY.md`)
 - Issue до кода и поиск дубля не обязательны
 - Обратная совместимость до первого релиза не нужна и вредна: команды `bro`,
   имена инструментов MCP, API, формат `brood.yaml`, схема БД и протокол гостя
   меняются сразу и целиком. Старые имена, алиасы, переходные поля и ветки
   «для прежних клиентов» не оставляются; то, что перестало быть нужным,
   удаляется, а не скрывается
 - В силе остаются: секреты только в `.env`, сверка владения перед удалением
   контейнеров, Git-идентичность оператора

Режим снимается удалением этого раздела.

## Объекты

 - **Пользователь** — локальная учётная запись; `is_admin` — единственная
   глобальная роль
 - **Проект** — окружение роя: репозиторий, участники, лимиты, секреты,
   образы. Объявляется плейбуком `brood.yaml` в корне репозитория
   (переменная `vars.brood`), синхронизируется `bro build`
 - **Рой** — группа агентов проекта и область шины сообщений. У роя один
   владелец; доступ есть у владельца и администратора. Ролей и ACL нет
 - **Агент** — один непривилегированный контейнер Proxmox с systemd-сервисом
   `brood-agent` (`brood-guest`), сессией Claude Code и терминалом
 - **Пул** — подключение Proxmox и бюджет ёмкости; только администратор
 - **Образ** — шаблон Proxmox, собранный плейбуком проекта; агенты проекта —
   его связанные клоны

Слова «актор», «воркер», «нода» в интерфейсах не используются: везде «агент»
и «пул».

## Структура

 - `go/` — Go-модуль `brood.dev/go`: сервер `brood` (`cmd/brood`), клиент
   `bro` (`cmd/bro`), агент `brood-guest` (`cmd/brood-guest`). Устройство,
   границы пакетов и закрытый список зависимостей — `docs/GO.md`. Сборка —
   `make -C go build`
 - `web/` — панель на React/TypeScript; её соглашения — `web/AGENTS.md`,
   описание — `docs/WEB.md`. Собранный single-file bundle лежит в
   `go/brood/server/static/index.html` и встроен в сервер
 - `brood/` — Python-инструменты разработки, вход — `bin/brood`: трекер и CI
   (`brood dev`). В продукт не входят.
   `brood/common` берёт только stdlib; `brood/dev` берёт `common` и себя
 - `brood.yaml` — плейбук образа самого brood и объявление его проекта
 - `.ci/` — шаги пайплайна скриптами, `.gitlab-ci.yml` их только зовёт;
   `deploy/` — служба systemd, принудительная команда выкладки и сборка
   страницы терминала (`docs/DEPLOY.md`)
 - `docs/` — по одному файлу на подсистему, UPPERCASE-слово
 - `.env` и `secrets/` — секреты установки; в git не попадают

## Правила

 - **MUST** Сервер, клиент и агент пишутся на Go в `go/`. Python остаётся
   только в инструментах разработки; пользовательские команды в
   Python-диспетчер не добавляются
 - **MUST** Библиотека возвращает данные и молчит; печатают только `cmd/`
   Go-бинарников и командлеты (пакеты `cli`) — иначе второй фронтенд начнёт
   парсить текст, разложенный для терминала
 - **MUST** Вывод — английский: его читает модель, не только человек.
   Комментарии — русские; godoc и справка команд — английские
 - **MUST** Отказ несёт причину тому, кто его читает: что произошло,
   изменилось ли что-нибудь и что делать. Строкой, не трассировкой, без
   служебных слов вроде `conflict:` и без сырого ответа провайдера
 - **MUST** Всё, что видит человек, называет объекты их именами, а не
   идентификаторами: рой — `проект/рой`, агент — именем
 - **MUST** Команда `bro` и инструмент MCP — одно и то же действие из одного
   каталога (`go/brood/command`). Команда только для человека живёт в
   `cmd/bro` и ходит в обычный HTTP API
 - **MUST** Сервер меняет в Proxmox только контейнеры с собственной меткой
   владения в описании и в своём пуле ресурсов; владение сверяется перед
   каждой записью. Неизвестный исход записи не повторяется вслепую
 - **MUST** Секреты установки — только в `.env`; секреты выкладки —
   защищённые переменные CI. Токен Proxmox и токены ботов — write-only для
   API: не возвращаются после записи, не попадают в логи и в контейнеры.
   Секреты проекта доставляются агенту при старте и не попадают в образ
 - **MUST** Свойство машины (путь, адрес) — настройка без дефолта в коде:
   зашитый дефолт отдаёт машину автора; отказ называет настройку
 - **MUST** Зависимости Go-модуля — минимальные, список закрыт
   `docs/GO.md`; новая зависимость — сначала запись туда и причина
 - **MUST** Панель: каждая сущность — плоский раздел главного меню; строка
   открывает боковую панель объекта; там, где возможен выбор, нет текстового
   поля; у полей формы есть значения по умолчанию и подсказки
 - **MUST** Ключ выкладки умеет одно: в `authorized_keys` машины деплоя у
   него `restrict,from=<builder>,command=brood-deploy`. Новое действие на
   машине — правка `deploy/brood-deploy.sh`, а не второй ключ или шелл
 - **MUST** Python-командлеты модуля живут в его пакете `cli`
   (`brood/dev/cli/bug/list.py` → `brood dev bug list`), не зовут друг друга
   подпроцессом, относительных импортов нет
 - **MUST** Комментарий `#123` в теме коммита, без закрывающих слов
 - **MUST NOT** Никаких emoji; никаких КАПС кроме идентификаторов, статусов
   (`FAILED`) и MUST/SHOULD этого файла

## Процесс

Пока действует временный режим, он заменяет этот раздел. Обычный порядок:

 - Одна задача = один issue, до кода: шаги воспроизведения, ожидание, факт,
   доказательство, причина (когда подтверждена), что делать
 - Ветка задачи `[type]/[iid]-[slug]` от свежей main; один фикс = один слой
 - Тесты: Go — `cd go && go test ./...`, Python — `brood dev test`, панель —
   `brood dev web test`; для чистых функций сначала падающий тест
 - Перед PR: тесты, `ruff check`, ревью собственного диффа; при правках
   панели — проверка затронутых страниц в браузере на настоящем сервере и
   пересборка встроенного bundle

## Ловушки (каждая оплачена отладкой)

 - PVE держит замок на шаблоне, пока идёт клон: второй клон того же образа
   в это время получает отказ. Клоны одного образа идут по очереди
 - В Debian нет пакета `ttyd`: контейнер скачивает закреплённый статический
   бинарник и сверяет sha256
 - WebSocket к терминалу идёт только по HTTP/1.1: общий TLS-конфиг клиента
   с `h2` в ALPN ломает рукопожатие за nginx
 - Бронь операции на агенте снимается по её завершении при любом исходе:
   вечная бронь закрывает агенту терминал и шину, и снять её нечем
 - Сервер открывает свежую базу несколько секунд: проверка старта ждёт
   `/healthz` в цикле, а не один раз
 - `.env` хранит значения в кавычках (`BROOD_PUBLIC_HOST='brood.example.com'`)
   — парсер снимает кавычки, а не режет значение по первому `=`
 - Трасса джобы CI — сырой текст с `\r` секций: без `screen_lines` хвост
   лога — мусор маркеров
 - Идущий пайплайн с проваленной джобой вне deploy-стадии — это провал,
   а не «жди»: вердикт смотрит джобы, не только статус пайплайна
 - Тело задачи трекера пустым быть не может; перенос строк и бэктики едут
   `--body-file` или stdin, не аргументом
