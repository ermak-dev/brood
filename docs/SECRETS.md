# Проектные секреты

`bro secret` переносит механизм `mop secret` в серверное хранилище Brood.
Это данные приложения проекта, а не credentials установки, Proxmox или CI.
Управление доступно администратору через обычную HTTPS-сессию `bro`.
Проект указывается явно по ID или однозначному имени.

```sh
bro secret --project PROJECT var add APP_TOKEN --stdin
bro secret --project PROJECT var add APP_TOKEN --value-file /private/token
bro secret --project PROJECT var list
bro secret --project PROJECT var remove APP_TOKEN

bro secret --project PROJECT file add .env config/service.json
bro secret --project PROJECT file list
bro secret --project PROJECT file remove .env config/service.json
```

Значение переменной не принимается в argv. Ввод из stdin или файла удаляет
не более одного завершающего перевода строки. Остальное значение сохраняется
без изменения; переносы строк внутри переменной запрещены. Файлы передаются
как непрозрачные байты, с относительными путями от корня Git checkout.
Симлинки, устройства, FIFO и выход за корень не принимаются. Пакет добавления
проверяется целиком до записи. Мутации молчат; list показывает только имена,
размеры файлов и revision, никогда значения. Read/export API отсутствует.

Секреты не объявлены MCP tools и недоступны через `bro --guest secret`.
Обычное проектное членство само по себе не даёт права управлять ими.

## Доставка

Поддерживается управляемый Proxmox Claude Code runtime с новым guest image.
Изменения применяются при следующем старте приложения, restart или recycle,
а не инъекцией в работающий процесс. Обновление сервера не заменяет guest image
и не перезапускает существующих пользовательских акторов.

Root supervisor получает только секреты текущего проекта по scoped токену
актора: сервер проверяет UID, generation, актуальную привязку роя и namespace.
Пользовательская cookie не даёт доступа к этому endpoint. Проекция хранится
в `/run/brood/project-secrets.json`, владелец root, группа 1000, режим 0440.
Фиксированный UID 1000 wrapper применяет файлы и добавляет переменные только
в окружение конечного процесса Claude Code. В root supervisor, session helper,
аргументы tmux и образ значения не добавляются.

Переменные доступны и без checkout. Доставка файлов требует существующего Git
checkout в `/workspace/project`: до публикации байтов проверяются отсутствие
пути в индексе и фактическое действие ignore-правил. Пользовательский
`.gitignore` не переписывается. Отрицательные правила, раскрывающие секрет,
вызывают отказ. Служебные Git/Claude control paths, включая `.gitignore` на
любой глубине, не принимаются как имена секретов.

У актора с origin первый старт приложения клонирует его до применения
файлов ([PROXMOX.md](PROXMOX.md), «Origin и первый клон»), поэтому файловые
секреты работают и на новом акторе. Без checkout — origin не задан или клон
не удался — Claude запускается только с переменными, а терминал сообщает,
что файлы не доставлены; байты не публикуются. Они появятся на следующем
старте после успешного клона.

Файлы создаются с режимом 0600. Пользовательские файлы не перезаписываются:
для замены или удаления ранее доставленного файла его hash должен совпадать
с учтённым. Manifest и журнал восстановления находятся вне workspace, в
приватном каталоге `/workspace/home/.config/brood/`, содержат имена и hashes,
но не значения. Журнал позволяет повторить прерванное применение. Симлинки,
hard links и небезопасные компоненты пути вызывают отказ. Linux filesystem
должна поддерживать `O_TMPFILE`; небезопасного fallback нет.

Native Substrate runtime пока не имеет приватного канала доставки. Запуск,
обновление, resume актора или golden template с секретами проекта отказывает,
а не помещает их в публичный template env и не пропускает молча.

## Границы доверия

Это не vault, скрывающий данные от самого актора. Его приложение и модель
с Read/Bash работают от UID 1000 и намеренно получают доступ к файлам и
окружению. Не выдавайте проекту credentials, которые его код не должен знать.
Git-ignore защищает обычный workflow, но не мешает доверенному актору самому
прочитать файл или выполнить `git add -f`.

SQLite и её snapshots содержат значения в открытом виде внутри приватного
хранилища. Шифрование at rest не заявляется. База создаётся с режимом 0600;
каталог, WAL, резервные копии и PVC должны оставаться приватными. Удаление
секрета не стирает исторические резервные копии.

Не допускаются переменные, меняющие identity, executable search, загрузчики,
интерпретаторы, Git execution policy и фиксированный model/proxy route.
Лимиты: 128 файлов и переменных, 512 KiB на файл, 2 MiB файлов в проекте,
16 KiB на значение переменной и 64 KiB на суммарное окружение секретов.
Имена файлов ограничены 1024 байтами, каждый компонент — 255 байтами.
Гостевое применение дополнительно ограничивает encoded manifest и Git excludes
64 KiB, журнал восстановления — 256 KiB. Переполнение, включая объединение
старых и новых имён для recovery, вызывает отказ до публикации байтов.

Приёмка использует только синтетические значения и собственные временные
ресурсы. Успех локальных CLI/server tests не доказывает доставку в работающий
Proxmox guest; это отдельная проверка закреплённого образа.
