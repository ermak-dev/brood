# Панель

Панель — веб-интерфейс brood. Через неё заводят проекты, рои и агентов,
открывают терминал агента, а администратор управляет пулами,
пользователями и шлюзом моделей. Объекты, о которых идёт речь, описаны
в [MODEL.md](MODEL.md).

Панель — приложение на React и TypeScript из каталога `web/`. Оно
собирается в один файл `index.html` со встроенными скриптами и стилями,
и этот файл встроен в бинарник сервера `brood`. Отдельно разворачивать
панель не нужно: сервер отдаёт её по адресу `/`, например
`https://brood.example.com/`. Маршруты панели живут во фрагменте адреса
(`/#/agents`), поэтому серверу достаточно одного файла.

Вход — по имени и паролю учётной записи brood. Сервер заново проверяет
права при каждом запросе; панель лишь скрывает то, что пользователю
недоступно.

## Разделы

Каждый объект — отдельный раздел с одной плоской таблицей. После входа
открывается раздел «Агенты».

| Раздел | Адрес | Кому виден | Что можно сделать |
|---|---|---|---|
| Проекты | `/#/projects` | всем | Посмотреть репозиторий, участников, лимиты и образы проекта с журналом сборки; перейти к роям проекта. Администратор создаёт проект, меняет участников и лимиты, удаляет образ и проект |
| Рои | `/#/swarms` | всем | Создать рой в проекте, скопировать его публичный Git SSH-ключ, перейти к агентам, удалить пустой рой. Пользователь видит свои рои, администратор — все |
| Агенты | `/#/agents` | всем | Создать агента (имя, рой, профиль пула, роль, репозиторий), открыть терминал или просмотр, запустить, остановить, сбросить, удалить |
| Роли | `/#/roles` | всем | Посмотреть роли, общие для всей установки. Администратор создаёт и редактирует их без выбора проекта, удаляет неиспользуемые роли |
| Пулы | `/#/pools` | администратору | Добавить подключение к Proxmox, активировать пул, приостановить размещение новых агентов и вернуть его, деактивировать пул, удалить подключение; посмотреть занятость |
| Пользователи | `/#/users` | администратору | Создать пользователя, сбросить пароль, выдать или снять права администратора, отключить, включить, удалить |
| Профиль | `/#/profile` | всем | Привязать чат Telegram и задать своего бота ([TELEGRAM.md](TELEGRAM.md)) |

Проект обычно создаётся не в панели, а командой `bro build` в репозитории
с `brood.yaml` ([BUILD.md](BUILD.md)). Поля формы подключения к Proxmox
описаны в [PROXMOX.md](PROXMOX.md).

На пустой странице панель показывает путь от пустой установки до
работающего агента: подключение и пул, проект, рой, агент.

## Как устроена работа с таблицами

Все таблицы устроены одинаково.

 - **Плоские таблицы.** У проекта и роя нет собственной страницы и
   вложенных таблиц. Ячейка родителя — ссылка на таблицу детей с
   фильтром: `/#/swarms?project=<id>`, `/#/agents?swarm=<id>`.
 - **Состояние в адресе.** Текстовый фильтр (`q`), фильтры-списки,
   столбец и направление сортировки (`sort`, `dir`), открытый объект
   (`open`) и форма создания (`create`) записаны в строке запроса. Вид
   таблицы можно сохранить в закладки или переслать ссылкой, он
   переживает перезагрузку. Кнопка «Назад» браузера закрывает панель
   объекта или форму.
 - **Строка открывает объект.** Щелчок по строке открывает боковую панель
   объекта. В ней сверху состояние, затем действия с пояснением в одну
   строку, сведения, команды `bro`, которые делают то же из терминала,
   и внизу отдельным блоком необратимые действия. Недоступное действие
   не исчезает, а называет причину.
 - **Формы в боковом листе.** Создание и правка открываются сбоку.
   Ошибка показывается рядом с полем; отказ сервера остаётся в форме
   вместе с введённым; закрытие формы с несохранёнными данными
   спрашивает подтверждение.
 - **Подтверждение.** Действия с последствиями (удаление, сброс,
   отключение) спрашивают подтверждение.
 - **Сводка.** Над таблицей агентов стоят счётчики: работают,
   запускаются, остановлены, с ошибкой. Щелчок по счётчику фильтрует
   таблицу, повторный — снимает фильтр.
 - **Клавиши.** `/` — перейти к фильтру, `n` — создать, стрелки —
   перемещение по строкам, `Enter` — открыть строку, `Esc` — закрыть,
   `?` — показать список клавиш.

На телефоне строки таблицы становятся карточками.

Таблица агентов обновляется сама раз в 4 секунды, пока вкладка видна.
Остальные таблицы обновляются кнопкой в шапке и после каждого действия.
Команды над агентом выполняются в фоне: панель сразу показывает
запрошенное состояние, а действительное — когда о нём сообщит сервер.

## Терминал и просмотр

У работающего агента два способа посмотреть на сессию, оба открываются
в новой вкладке из строки таблицы или из панели агента.

 - **Терминал** — сессия агента с вводом: видно, что делает Claude Code,
   и можно печатать. Ссылка
   `/api/swarms/<id>/proxy/actors/<имя>/?mode=rw` выдаёт краткосрочный
   пропуск и перенаправляет на страницу терминала. Пропуск действует
   10 минут и привязан к сессии входа; если агент остановлен или право
   на рой пропало, терминал не откроется.
 - **Просмотр** (`?mode=ro`) — снимок экрана агента простым текстом, без
   ввода. Ничего набранное агенту не попадает. Снимок не обновляется
   сам: нужно перезагрузить страницу.

Терминал доступен тем, кто управляет роем: владельцу и администратору.
То же из командной строки — `bro attach NAME` и `bro attach NAME --view`
([CLI.md](CLI.md)).

## Страницы шлюза моделей

Агенты обращаются к моделям через шлюз CLIProxyAPI, встроенный в сервер
через Go SDK. Панель brood выросла из панели управления этим шлюзом
(CLI Proxy API Management Center), и её страницы сохранены. Они видны
только администратору, в группах меню «Шлюз» и «Система»:

| Страница | Адрес | Чем управляет |
|---|---|---|
| Статистика шлюза | `/#/dashboard` | Трафик, поставщики, учётные данные |
| Поставщики AI | `/#/ai-providers` | Маршрутизация к поставщикам моделей и их ключи |
| Файлы аутентификации | `/#/auth-files` | Учётные данные поставщиков, исключённые модели, псевдонимы моделей |
| OAuth вход | `/#/oauth` | Авторизация у поставщиков через OAuth |
| Управление квотами | `/#/quota` | Остатки квот у поставщиков |
| Просмотр логов | `/#/logs` | Журнал запросов шлюза |
| Панель конфигурации | `/#/config` | Настройки шлюза, в том числе в виде YAML |
| Плагины, магазин плагинов | `/#/plugins`, `/#/plugin-store` | Плагины шлюза; показываются, если шлюз их поддерживает |
| Информация системы | `/#/system` | Версия и диагностика |

Эти страницы работают с Management API шлюза (`/v8/management`), но не
напрямую. Браузер обращается к серверу brood, а сервер, убедившись, что
запрос пришёл от администратора, пересылает его на локальный порт SDK
и подставляет `CLIPROXY_MANAGEMENT_KEY`. Ключ в браузер не попадает.
Если шлюз или ключ управления не настроены, его страницы отвечают 503,
но остальная панель работает. См. [GATEWAY.md](GATEWAY.md).

## Разработка

Нужен Bun версии 1.3.14 (закреплена в `web/package.json`). Команды
выполняются в каталоге `web/`:

| Команда | Что делает |
|---|---|
| `bun install --frozen-lockfile` | Ставит зависимости по `bun.lock` |
| `bun run dev` | Сервер разработки Vite |
| `bun run type-check` | Проверка типов (`tsc --noEmit`) |
| `bun run lint` | ESLint |
| `bun run build` | Проверка типов и сборка в `web/dist/index.html` |

Панель обращается к API по тому же адресу, с которого загружена, а
в `vite.config.ts` прокси к серверу не настроен. Поэтому изменения
проверяют на собранной панели, встроенной в сервер.

Тесты в `web/tests` на время текущей перестройки проекта не
поддерживаются.

### Как сборка попадает в сервер

Сервер встраивает файл `go/brood/server/static/index.html` директивой
`go:embed`. Этот файл хранится в репозитории, поэтому `go build`
работает без Bun, но берёт ту панель, которая лежит в файле.

Обновить его можно двумя способами:

 - `bin/brood dev web build` запускает сборку в контейнере с тем же
   образом Bun, что закреплён в `deploy/Dockerfile.go`, и копирует
   `web/dist/index.html` в `go/brood/server/static/index.html`. Нужен
   Docker.
 - Вручную: `bun run build` в `web/`, затем скопировать
   `web/dist/index.html` в `go/brood/server/static/index.html`.

Пересобирать нужно после любого изменения в `web/`, перед сборкой
сервера командой `go build`. Образ сервера из `deploy/Dockerfile.go`
собирает панель сам на первом этапе и подставляет свежий файл, так что
в образ устаревшая панель не попадёт. Файлы в `web/dist/` и
`go/brood/server/static/index.html` руками не правят. Сборка сервера
описана в [GO.md](GO.md).

Сборка должна оставаться одним файлом: нельзя добавлять разбиение кода
и внешние файлы, которые пришлось бы раздавать отдельно.

### Локализация

Тексты интерфейса лежат в `web/src/i18n/locales/` в шести файлах:
`en.json`, `ru.json`, `zh-CN.json`, `zh-TW.json`, `ko.json`, `vi.json`.
Новый ключ добавляется во все шесть. Запасной язык — `zh-CN`: ключ,
пропущенный в файле выбранного языка, показывается по-китайски.

К brood относятся:

 - раздел `brood` — таблицы, панели объектов, формы и все пять разделов
   (`brood.projects`, `brood.swarms`, `brood.agents`, `brood.pools`,
   `brood.users`);
 - раздел `profile` — страница профиля и Telegram;
 - в `nav` — ключи `projects`, `swarms`, `agents`, `pools`, `users`,
   `gateway_dashboard`; в `nav_groups` — `brood`.

Остальные разделы принадлежат страницам шлюза.

### Как добавить страницу

Код brood лежит в `web/src/features/brood/`, страница профиля —
в `web/src/features/profile/`, вызовы API сервера —
в `web/src/services/brood/`.

Новая сущность — это новая плоская таблица, а не страница с собственной
вёрсткой. Она собирается из общего блока `web/src/features/brood/table/`:

| Файл | Что даёт |
|---|---|
| `TablePage.tsx` | Страница-таблица: шапка, сводка, фильтры, сортировка, строки, пустое состояние, клавиши |
| `EntityPanel.tsx` | Боковая панель объекта с действиями и сведениями |
| `dialogs.tsx` | Форма в боковом листе (`FormSheet`) и подтверждение (`ConfirmDialog`) |
| `useTableQuery.ts` | Состояние таблицы в строке запроса |
| `formState.tsx` | Состояние формы и проверка полей |
| `format.tsx` | Относительное время и обрезка длинных значений |

Порядок:

1. Добавить типизированные вызовы API в `web/src/services/brood/`.
   Компоненты не вызывают `fetch` сами.
2. Написать страницу в `web/src/features/brood/` на `TablePage`:
   столбцы, фильтры, панель объекта, форма создания.
3. Добавить маршрут в `web/src/router/MainRoutes.tsx` и пункт меню
   в `web/src/components/layout/navigation.ts`. Если раздел должен быть
   виден не только администратору, добавить его адрес в `memberPaths`
   в `web/src/features/brood/routes.ts`.
4. Добавить тексты во все шесть файлов локализации.
5. Пересобрать панель в сервер.

В интерфейсе везде пишется «агент»; в API сервера агент называется
`actor`. Остальные соглашения для того, кто
правит код панели, — в [`web/AGENTS.md`](../web/AGENTS.md).
