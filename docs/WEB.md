# Web

Панель встроена в Go-сервер: `go/brood/server/static/index.html` через
`go:embed`. Отдельных React/TypeScript/Bun-зависимостей, frontend-сборки
и форка панели CLIProxyAPI больше нет. Сервер отдаёт панель и API одним
origin; браузер не хранит management-ключ провайдера.

## Вход и права

- `GET /api/auth/session` получает состояние сессии и CSRF bootstrap.
- `POST /api/auth/login` входит по локальному имени и паролю.
- `POST /api/auth/logout` отзывает сессию.
- Изменяющие запросы передают `X-CSRFToken` и проверяемый Origin.
- Сессионная cookie HttpOnly; пароли не сохраняются в browser storage.

Администратор управляет пользователями и проектами, добавляет/исключает
участников, сбрасывает пароли, блокирует/включает учётные записи и передаёт
рой другому владельцу. Последнего активного администратора нельзя
заблокировать или лишить прав. Эти ограничения проверяет сервер, не UI.

Участник проекта создаёт и видит собственные рои. Членство само по себе
не открывает чужие рои. Панель показывает акторов доступного роя и действия
suspend/resume/delete и terminal. Отсутствующий Substrate не превращается
в фиктивный успех: неудачная операция остаётся с состоянием ошибки для retry.

Это минимальная панель, а не функциональная копия удалённого frontend.
Редакторов templates/policies/tags, управления worker pools и провайдерами
LLM в интерфейсе пока нет. Доступные серверные операции определяются Go API;
отсутствующую страницу нельзя считать реализованной по наличию endpoint.
LDAP, OAuth и отдельного JWT issuer нет.

## Терминалы

HTML актора не получает browser-полномочия панели. После авторизации сервер
выдаёт привязанный к сессии, рою и актору короткоживущий actor-view ticket.
Ответ обязательно имеет CSP sandbox без `allow-same-origin`; cookies актора
и управляющие browser-заголовки отбрасываются. Assets и WebSocket ограничены
тем же ticket. Полная модель отзыва доступа и ограничения — `docs/GO.md`.

Терминал — управление актором, не read-only доступ. Ticket URL нельзя
писать в access logs. Logout, блокировка, исключение из проекта и смена
владельца отзывают доступ; текущий stream перепроверяется не позднее 60 секунд.

## Проверки

```sh
make -C go fmt-check vet test build
cd go && go test ./acceptance -count=1 -v
```

Пакетные тесты проверяют HTTP/CSRF/auth/ownership и заголовки изоляции.
Отдельный браузерный протокол проверяет настоящий Chromium и ttyd;
наличие infrastructure fake в стенде всегда обозначается явно.

Старые `/auth/*`, `/admin/*` и management/OAuth-маршруты CLIProxyAPI не
являются API нового сервера. Удаление исходников не переключает живой
production ingress автоматически; миграция описана в `docs/DEPLOY.md`.
