# Объектная модель

В brood шесть объектов: пользователь, проект, рой, агент, пул и образ. Этот
документ описывает, что каждый из них хранит, кто может им управлять и через
какие состояния проходит агент.

```text
пользователь --участник--> проект --> рой (один владелец) --> агент
                             |                                  |
                             +--> образ (в пуле) <--клон--------+
пул (подключение Proxmox, бюджет) <----------размещён-----------+
```

## Пользователи

Пользователь — локальная учётная запись сервера: имя и пароль. Глобальная роль
одна: администратор. Первого администратора создаёт команда сервера
`brood bootstrap-admin`, остальных пользователей администратор заводит
в панели, раздел «Пользователи».

Отключённый пользователь не может ничего, даже если он администратор.

## Проекты

Проект — окружение, в котором работают рои. У проекта есть:

- **Имя**: строчные латинские буквы, цифры и дефисы внутри, до 63 символов.
- **Участники**: пользователи, которым проект виден. Участник может создавать
  в проекте рои. Ролей внутри проекта нет. Состав меняет администратор.
- **Репозиторий**: необязательный HTTPS-адрес Git-репозитория. Его клонируют
  в рабочую копию новых агентов и из него собирают образ.
- **Git credential**: необязательная ссылка на учётные данные Git, которые
  хранит сервер ([SECRETS.md](SECRETS.md)).
- **Лимиты**: необязательные пределы на число роёв, число агентов, процессор
  и память.
- **Секреты**: переменные окружения и файлы, которые агент получает при
  запуске сессии ([SECRETS.md](SECRETS.md)).
- **Образы**: шаблоны контейнеров проекта ([BUILD.md](BUILD.md)).

Проект создаёт и меняет администратор: командой `bro build` из `brood.yaml`
или в панели. Участник может выполнить `bro build`, только если объявление
в `brood.yaml` совпадает с тем, что уже записано на сервере.

Проект удаляет администратор. Сначала нужно удалить рои и образы проекта.

### Лимиты

Каждый лимит — неотрицательное целое или отсутствие предела. Ноль запрещает
любое резервирование.

| Лимит | Что считается |
| --- | --- |
| Рои | Неудалённые рои проекта |
| Агенты | Все существующие агенты этих роёв, в любом состоянии |
| Процессор | Сумма долей процессора этих агентов, в тысячных ядра |
| Память | Сумма долей памяти этих агентов, в байтах |

Остановленный агент продолжает занимать лимит: место освобождает только
удаление. Проверка выполняется при создании роя и агента. Если лимит снизили
ниже занятого, существующие агенты продолжают работать, но новые не создаются.

Сборочный контейнер образа в лимиты проекта и в бюджет пула не входит.

## Рои

Рой — группа агентов одного проекта. Агенты роя видят друг друга и могут
переписываться; агенты разных роёв друг друга не видят.

- У роя ровно один владелец — пользователь, который его создал.
- Доступ к рою есть у владельца и у администратора. Других ролей и списков
  доступа нет: участник проекта не видит чужие рои.
- Имя роя уникально в пределах проекта.
- Владелец или администратор может передать рой другому пользователю, если
  тот участник проекта или администратор.
- Удалить можно только рой без агентов.

Сообщение агента с адресатом `operator` приходит владельцу роя в Telegram
([TELEGRAM.md](TELEGRAM.md)).

## Агенты

Агент — один непривилегированный LXC-контейнер Proxmox с Debian и systemd.
В контейнере работает служба `brood-agent.service` (бинарник `brood-guest`).
Она держит сессию Claude Code от имени пользователя `actor` (UID 1000), отдаёт
терминал для браузера и `bro attach` и поддерживает исходящее соединение
с сервером, по которому идут сообщения и команды.

Имя агента — строчные латинские буквы, цифры и дефисы, до 63 символов,
уникальное в рое. Имя `operator` занято: так на шине сообщений называется
владелец роя.

Каталоги внутри контейнера:

| Путь | Что там |
| --- | --- |
| `/workspace/project` | Рабочая копия репозитория; рабочий каталог Claude Code |
| `/workspace/home` | Домашний каталог пользователя `actor` |
| `/opt/brood/bin` | `bro` и `claude`, которые агент скачивает с сервера |

Сеть агента не ограничивается.

### Роли

У каждого агента одна роль его проекта. Роль задаёт имя, дополнительную
инструкцию для новой сессии и разрешения на команды brood. Имя роли не даёт
прав. Права применяются со следующего вызова; новая инструкция вступает в
силу при следующем запуске сессии. Правка роли не прерывает работу.

Новый проект получает две роли: «Агент» (по умолчанию) и «Мастер». Агент
видит состав роя, пишет соседям и оператору и читает свой терминал. Мастер
может читать терминалы роя, добавлять исполнителей и управлять теми, кого
создал сам. Сброс и удаление выключены в обеих начальных ролях. Добавленный
мастером агент получает роль по умолчанию и размещается в пуле мастера.

Ролями управляет администратор. Делегированные разрешения действуют, пока
назначивший их администратор активен и сохраняет доступ к рою. Роль не
ограничивает shell, Git или сторонние серверы MCP. Области разрешений
описаны в [MCP.md](MCP.md).

### Репозиторий агента и первое клонирование

У агента есть origin — адрес репозитория для рабочей копии. Он выбирается при
создании: явно заданный (`bro add --origin URL`), иначе origin мастера, который
создаёт агента, иначе репозиторий проекта. Origin может быть пустым, тогда
рабочая копия остаётся пустой.

Origin должен быть HTTPS-адресом. Доступ бывает двух видов:

- **через сервер** — когда origin совпадает с репозиторием проекта и для него
  на сервере настроены учётные данные. Агент обращается к Git-шлюзу сервера
  и учётных данных не видит ([SECRETS.md](SECRETS.md));
- **напрямую** — в остальных случаях агент клонирует репозиторий сам, без
  учётных данных.

Клонирование выполняется при первом запуске сессии, пока каталог
`/workspace/project` пуст. Если оно не удалось, Claude Code всё равно
запускается, а попытка повторяется при следующем запуске сессии.

Если у установки задан домен в `BROOD_ACTOR_GIT_DOMAIN`, агент получает
Git-идентичность `brood ИМЯ <ИМЯ@домен>`.

### Действия над агентом

| Действие | Что происходит | Контейнер | Рабочая копия и домашний каталог |
| --- | --- | --- | --- |
| `stop` | Контейнер останавливается | остаётся | сохраняются |
| `start` | Остановленный контейнер запускается, агент подключается заново | тот же | сохраняются |
| `restart` | Сессия Claude Code перезапускается внутри работающего контейнера; секреты проекта перечитываются | тот же, не останавливается | сохраняются |
| `reset` | Контейнер удаляется и создаётся заново из того же образа или шаблона, из которого агент был создан | новый | уничтожаются |
| `rm` | Контейнер удаляется вместе с записью агента | удалён | уничтожаются |

`reset` и `rm` необратимы и требуют подтверждения. `reset` сохраняет имя,
роль, origin, пул и номер контейнера агента.

### Поколение

У агента есть счётчик поколения. Он начинается с 1 и увеличивается при каждом
`reset`. Поколение входит в адрес соединения агента и в его токен, поэтому
контейнер прошлого поколения не может подключиться к серверу и получить
секреты. `stop`, `start` и `restart` поколение не меняют.

### Состояния

| Состояние | Что значит |
| --- | --- |
| `provisioning` | Контейнер создаётся или запускается, либо сервер ставит в него агента и ждёт подключения |
| `running` | Контейнер работает, агент подключён к серверу |
| `stopping` | Контейнер останавливается |
| `stopped` | Контейнер остановлен; рабочая копия цела |
| `deleting` | Контейнер удаляется |
| `error` | Операция не завершилась; причина — в коде и тексте ошибки |

Удалённый агент из списков исчезает.

Сервер сверяет записанное состояние с Proxmox в фоне. Операцию, исход которой
Proxmox не подтвердил, он вслепую не повторяет: агент переходит в `error`
с объяснением, что делать.

### Коды ошибок

Вместе с состоянием `error` агент несёт код и текст на английском. `bro agents`
показывает текст в столбце `NOTE`, панель — перевод по коду.

| Код | Что произошло | Что делать |
| --- | --- | --- |
| `ownership` | Контейнер в Proxmox больше не соответствует созданному: изменили описание, диск или сеть, либо он вышел из пула ресурсов brood. Сервер ничего не менял | Восстановить контейнер в Proxmox или удалить агента |
| `permission` | Proxmox отказал: у API-токена brood нет нужного права. Ничего не изменено | Администратору проверить роли токена и повторить |
| `task_failed` | Proxmox начал операцию и сообщил о сбое | Посмотреть журнал задачи контейнера в Proxmox, затем повторить или удалить агента |
| `task_pending` | Proxmox всё ещё выполняет операцию (дольше 15 минут). Сервер продолжает ждать | Ничего |
| `agent_waiting` | Контейнер запущен, но пока не отвечает по SSH. Сервер поставит агента, как только тот ответит | Ничего |
| `agent_install` | Установка агента в контейнер не удалась; текст называет шаг | Остановить и запустить агента; если повторяется, проверить контейнер |
| `agent_not_connected` | Агент не подключился за две минуты после запуска контейнера | Остановить и запустить агента; если повторяется, проверить службу `brood-agent` в консоли контейнера |
| `uncertain` | Proxmox не подтвердил, началась ли операция: запрос не прошёл или истёк срок | Если контейнера в Proxmox нет, удалить агента; иначе подождать и обновить список |
| `provider_unavailable` | Сервер не смог связаться с Proxmox. Он повторяет попытки сам | Ничего, если не затягивается |
| `other` | Другая причина; смотреть текст ошибки | По тексту |

## Пулы

Пул — подключение к одному узлу Proxmox VE и бюджет ресурсов на нём. Пул
хранит адрес API, токен, узел, пул ресурсов Proxmox, хранилище, сетевой мост,
базовый шаблон контейнера и ёмкость: число агентов, процессор, память и диск.
Настройка описана в [PROXMOX.md](PROXMOX.md).

Ёмкость делится между агентами поровну. Доля агента — ёмкость пула, делённая
на предельное число агентов и округлённая вниз до целого ядра, мебибайта
памяти и гибибайта диска. Например, пул на 3 агента, 6 ядер и 6 ГиБ памяти
даёт каждому агенту 2 ядра и 2 ГиБ. Доля не может быть меньше одного ядра.

Состояния пула:

- `enabled` — в пуле размещаются новые агенты;
- `draining` — новые агенты не размещаются, существующие продолжают работать,
  но остановленного агента в таком пуле запустить нельзя.

Пулами управляет только администратор: создаёт и удаляет в панели, переводит
между состояниями командами `bro pool drain` и `bro pool enable`.

## Образы

Образ — шаблон контейнера Proxmox, собранный для проекта в конкретном пуле.
Новый агент проекта в этом пуле создаётся связанным клоном последнего готового
образа. Если готового образа нет, агент создаётся из базового шаблона пула.
Сборка и состояния образа описаны в [BUILD.md](BUILD.md).

## Кто что может

| Действие | Администратор | Владелец роя | Участник проекта | Остальные |
| --- | --- | --- | --- | --- |
| Управлять пользователями | да | — | — | — |
| Подключать Proxmox, управлять пулами | да | — | — | — |
| Создавать, менять и удалять проекты, их участников, репозиторий и лимиты | да | — | — | — |
| Управлять секретами и Git credentials проекта | да | — | — | — |
| Видеть проект, его участников, лимиты и образы | да | — | да | — |
| Собирать и удалять образы проекта | да | — | да | — |
| Создавать рой в проекте | да | — | да | — |
| Видеть рой и его агентов | да | да | — | — |
| Создавать агентов, управлять ими, писать им, открывать терминал | да | да | — | — |
| Назначать роли с делегированными правами | да | — | — | — |
| Передавать и удалять рой | да | да | — | — |

Владелец роя, исключённый из проекта, сохраняет доступ к своему рою, но новый
рой в проекте создать не может.
