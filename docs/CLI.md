# Клиент bro

`bro` — клиент командной строки brood. Им человек входит на сервер, создаёт
рои и агентов, пишет агентам, открывает их консоль и собирает образы проекта.
Тот же бинарник работает внутри контейнера агента: так агент обращается
к серверу от своего имени.

Объекты, с которыми работает `bro`, описаны в [MODEL.md](MODEL.md).

## Установка

`bro` — один статический бинарник без зависимостей. Он собирается из
Go-модуля в каталоге `go/`:

```sh
make -C go build      # go/bin/bro и go/bin/brood
```

Положите `go/bin/bro` в каталог из `PATH`. Устройство модуля — в
[GO.md](GO.md).

## Вход и сессия

```sh
bro login brood.example.com
```

Команда спрашивает имя пользователя и пароль и сохраняет сессию для этого
сервера. Пароль не сохраняется. Адрес без схемы считается HTTPS; `http://`
допустим только для локального адреса. Если сертификат сервера выпущен своим
центром сертификации, укажите его файл: `bro login brood.example.com --ca ca.pem`.
`bro` запомнит его вместе с сессией.

Сессии лежат в `$XDG_STATE_HOME/brood/sessions`, по умолчанию
`~/.local/state/brood/sessions`. Сервер, на который вошли последним,
становится текущим: остальные команды обращаются к нему. `bro login` без
адреса входит на текущий сервер заново.

`bro logout` завершает сессию на сервере и удаляет её с диска.

## Текущий рой

Команды над агентами действуют в одном рое — текущем. Он выбирается так,
первое подходящее правило побеждает:

1. опция `-s NAME` (или `--swarm NAME`);
2. переменная окружения `BROOD_SWARM`;
3. рой, выбранный командой `bro join`; выбор запоминается для сервера;
4. единственный доступный рой.

Если ни одно правило не сработало, команда отказывает и перечисляет доступные
рои. Рой называют именем, парой `проект/рой` или идентификатором. Имя, которое
встречается в нескольких проектах, нужно уточнить парой `проект/рой`.

`bro status` показывает сервер, пользователя, текущий рой, источник выбора
и агентов роя:

```text
server  https://brood.example.com
user    admin (administrator)
swarm   brood/main (the only swarm)

NAME     ROLE   STATE    POOL   CT   AGE
agent-1  agent  running  brood  107  1h
agent-2  agent  running  brood  108  1h
```

## Команды

`bro help` печатает обзор, `bro COMMAND --help` — аргументы команды и пример.
Опция `--json` у списков печатает их в JSON.

### Сессия

| Команда | Что делает |
| --- | --- |
| `bro login [SERVER] [--ca FILE]` | Войти и запомнить сервер |
| `bro logout [SERVER]` | Завершить сессию на сервере и забыть её |
| `bro status [-s SWARM]` | Показать сервер, пользователя, текущий рой и его агентов |
| `bro diagnose` | Показать, какой сервер и какую сессию использует `bro`; без обращения к сети |
| `bro completion bash\|zsh` | Напечатать скрипт дополнения для оболочки |

```sh
bro login brood.example.com
bro status
```

### Рои

| Команда | Что делает |
| --- | --- |
| `bro swarms [--json]` | Список доступных роёв; `*` отмечает текущий |
| `bro join [SWARM]` | Выбрать текущий рой; без аргумента — показать его |
| `bro swarm add NAME [--project NAME]` | Создать рой; вы становитесь владельцем |
| `bro swarm rm NAME [--yes]` | Удалить рой, в котором нет агентов |

Проект нового роя — названный в `--project`, иначе единственный доступный,
иначе `brood.project` из `./brood.yaml`. Новый рой становится текущим, если
текущий ещё не выбран командой `bro join`.

```sh
bro swarm add review --project brood
bro join brood/review
```

### Агенты

| Команда | Что делает |
| --- | --- |
| `bro agents [--all] [--json] [-s SWARM]` | Список агентов роя; `--all` — агенты всех доступных роёв |
| `bro add [NAME] [--pool NAME] [--role agent\|master] [--origin URL] [--no-wait] [-s SWARM]` | Создать агента и дождаться, пока он заработает |
| `bro rm NAME... [--yes] [-s SWARM]` | Удалить агентов вместе с контейнерами |
| `bro start NAME... [-s SWARM]` | Запустить остановленных агентов; рабочая копия сохраняется |
| `bro stop NAME... [-s SWARM]` | Остановить агентов; контейнеры и рабочие копии сохраняются |
| `bro restart NAME [-s SWARM]` | Перезапустить сессию агента в том же контейнере |
| `bro reset NAME [--yes] [-s SWARM]` | Заменить контейнер новым; рабочая копия теряется |

Аргументы `bro add`:

| Аргумент | Значение |
| --- | --- |
| `NAME` | Имя агента; по умолчанию первое свободное `agent-N` |
| `--pool NAME` | Пул для агента; по умолчанию единственный пул, принимающий агентов |
| `--role agent\|master` | Роль; по умолчанию `agent`. Мастера создаёт только администратор |
| `--origin URL` | HTTPS-адрес Git-репозитория для рабочей копии; по умолчанию репозиторий проекта |
| `--no-wait` | Вернуться сразу, не дожидаясь запуска |

`bro add` показывает смену состояний одной строкой и ждёт `running` или
`error`. Ctrl-C прекращает ожидание, но не создание агента.

```sh
bro add reviewer --pool brood
bro stop agent-1 agent-2
bro reset agent-1
```

`bro rm` и `bro reset` спрашивают подтверждение. Без терминала подтверждение
невозможно: передайте `--yes`.

Столбцы `bro agents`: `NAME`, `ROLE`, `STATE`, `POOL`, `CT` (номер контейнера
в Proxmox), `AGE`. Если у какого-то агента ошибка, добавляется столбец `NOTE`
с её текстом. Состояния и коды ошибок — в [MODEL.md](MODEL.md).

### Работа с агентом

| Команда | Что делает |
| --- | --- |
| `bro attach NAME [--view] [-s SWARM]` | Открыть консоль агента в этом терминале |
| `bro send [--wait SECONDS] [-s SWARM] NAME MESSAGE...` | Отправить сообщение агенту |
| `bro tail NAME [-n LINES] [-f] [--grep TEXT] [-s SWARM]` | Показать последние строки вывода агента |
| `bro slash NAME COMMAND [-s SWARM]` | Отправить слэш-команду в сессию агента |
| `bro mcp [-s SWARM]` | Отдать эти команды модели как инструменты MCP через stdio |

**attach.** Открывает настоящую консоль сессии агента: всё набранное уходит
агенту, включая Ctrl-C и Ctrl-D. Ctrl-] отключает консоль и оставляет агента
работать. Команде нужен терминал на вводе и выводе и агент в состоянии
`running`. С `--view` экран только показывается и обновляется раз в две
секунды, ввод агенту не уходит; выйти можно через Ctrl-] или Ctrl-C.

```sh
bro attach agent-1
```

**send.** Сообщение — все слова после имени агента, как набраны. Опции стоят
перед именем. Одиночный `-` вместо сообщения читает его со стандартного ввода.
Команда сообщает, доставлено ли сообщение, а не ответ агента: ответ смотрят
через `bro tail` или `bro attach`. `--wait SECONDS` (от 0 до 300) ждёт, пока
агент закончит текущую работу и освободится.

```sh
bro send agent-1 run the tests and report
git diff | bro send agent-1 -
```

Возможные ответы: `delivered to NAME`, `NAME is not connected; not sent`
и `sent to NAME; delivery not confirmed, check with: bro tail NAME`. В двух
последних случаях статус выхода 1.

**tail.** Показывает снимок экрана агента: по умолчанию 40 последних строк,
`-n` — от 1 до 10000. `-f` дописывает новые строки до Ctrl-C, `--grep TEXT`
оставляет строки, содержащие текст.

```sh
bro tail agent-1 -n 100 -f
```

**slash.** Отправляет слэш-команду Claude Code; команду с аргументами берут
в кавычки.

```sh
bro slash agent-1 /clear
```

**mcp.** Подключает brood к модели на машине человека. Инструменты действуют
в текущем рое, который выбирается заново на каждый вызов. Подробности —
в [MCP.md](MCP.md).

```sh
claude mcp add brood -- bro mcp
```

### Проект

| Команда | Что делает |
| --- | --- |
| `bro projects [--json]` | Список доступных проектов |
| `bro build [--pool NAME] [--ref COMMIT] [--no-wait] [--no-secrets]` | Объявить проект из `./brood.yaml` и собрать образ агента |
| `bro build --plan` | Напечатать разобранное объявление в JSON, без обращения к серверу |
| `bro image list [--project NAME] [--json]` | Список образов проекта |
| `bro image rm IMAGE [--project NAME]` | Удалить образ |
| `bro secret --project ID_OR_NAME file\|var\|git add\|list\|remove ...` | Управлять секретами проекта |

`bro build` и образы описаны в [BUILD.md](BUILD.md), `bro secret` —
в [SECRETS.md](SECRETS.md).

```sh
bro build --pool brood
bro image list
bro secret --project brood var list
```

### Администратор

| Команда | Что делает |
| --- | --- |
| `bro pools [--json]` | Список пулов с состоянием и загрузкой |
| `bro pool drain NAME` | Перестать размещать в пуле новых агентов; существующие продолжают работать |
| `bro pool enable NAME` | Снова размещать агентов в пуле |
| `bro server diagnose` | Проверить базу данных сервера и соединение с агентами |

Столбцы `AGENTS`, `CPU` (ядра) и `MEMORY` в `bro pools` показывают занятое
из предела:

```text
NAME   STATE    AGENTS  CPU  MEMORY
brood  enabled  2/3     4/6  4/6G
```

Пулы создаёт администратор в панели ([PROXMOX.md](PROXMOX.md)).

## Сценарии

### Первый день

```sh
bro login brood.example.com
bro projects                 # проекты, в которых вы участник
bro swarm add main --project my-project
bro add                      # agent-1 в единственном пуле
bro attach agent-1
```

Если проекта ещё нет, его объявляет администратор: `bro build` в корне
репозитория с `brood.yaml`.

### Ежедневная работа

```sh
bro status
bro send agent-1 fix the failing test in pkg/store and report
bro tail agent-1 -f
bro attach agent-1           # когда нужно вмешаться руками
bro stop agent-1             # в конце дня; рабочая копия сохранится
bro start agent-1
```

### Несколько роёв

```sh
bro swarms
bro join my-project/review   # дальше команды идут в этот рой
bro agents
bro -s main agents           # разовое обращение к другому рою
bro agents --all
```

Для сценария удобна переменная окружения: `BROOD_SWARM=main bro agents`.

### Проект и образ

```sh
bro build --plan             # проверить brood.yaml без сервера
bro build                    # объявить проект и собрать образ из HEAD
bro image list
bro reset agent-1            # пересоздать контейнер агента
bro add agent-2              # новый агент — клон последнего готового образа
```

### Уборка

```sh
bro rm agent-1 agent-2
bro swarm rm my-project/review
bro image list
bro image rm IMAGE           # когда клонов образа не осталось
bro logout
```

## Статусы выхода

| Статус | Значение |
| --- | --- |
| 0 | Команда выполнена |
| 1 | Отказ или ошибка; причина одной строкой в stderr с префиксом `bro:` |
| 2 | Нет входа: сессии нет, она истекла или имя и пароль неверны |

`bro send` возвращает 1, когда доставка не подтверждена, `bro build` — когда
образ не стал готовым. Если сервер не подтвердил исход команды, `bro` пишет
`the outcome is not confirmed; check before retrying`: проверьте состояние
агента, прежде чем повторять.

## Дополнение в оболочке

```sh
source <(bro completion bash)    # bash
source <(bro completion zsh)     # zsh
```

Скрипт дополняет команды, имена роёв и имена агентов. Имена он запрашивает
у сервера и молчит, если сервер недоступен.

Цвет в таблицах включается только в терминале; переменная `NO_COLOR` его
выключает.

## Режим гостя

Внутри контейнера агента `bro` работает в режиме гостя: его включает опция
`--guest` или `BROOD_EXECUTION_MODE=guest`. В этом режиме нет входа и выбора
роя: команды идут через локальный брокер `brood-guest` на сервер от имени
агента и действуют в его рое. Доступны `agents`, `send`, `tail`, `slash`,
`add`, `rm`, `start`, `stop`, `restart`, `reset`, `diagnose`, `mcp`
и `build --plan`; что из этого разрешено, зависит от роли агента
([MODEL.md](MODEL.md)). Адресат `operator` в `send` — владелец роя. Аргументы
в этом режиме задаются так, как их показывает `bro --guest COMMAND --help`.
Claude Code в контейнере получает эти команды как инструменты MCP
([MCP.md](MCP.md)).
