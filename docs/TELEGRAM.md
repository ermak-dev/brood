# Telegram

Telegram в brood — канал между владельцем роя и агентами этого роя.
Владелец пишет агенту из личного чата с ботом, агент отвечает владельцу
в тот же чат. Больше Telegram ни для чего не используется: уведомлений
о событиях бот не присылает.

Понятия «рой», «агент» и «владелец» описаны в [MODEL.md](MODEL.md),
команда `send` и её гарантии — в [MCP.md](MCP.md).

## Боты

Сообщения идут через бота Telegram. Сервер сам опрашивает Bot API
(long polling), входящий адрес и webhook ему не нужны.

Ботов может быть два вида:

 - **Бот установки** — один на весь сервер, его токен задаёт
   администратор сервера в настройках. Им пользуются все, у кого нет
   своего бота.
 - **Свой бот** — бот пользователя. Пользователь создаёт его у
   `@BotFather` и сохраняет токен на странице «Профиль». Свой бот важнее
   бота установки.

Один бот не может быть своим у двух пользователей, и бот установки
нельзя сохранить как свой.

Настройки сервера:

| Настройка | Значение | По умолчанию |
|---|---|---|
| `BROOD_TELEGRAM_BOT_TOKEN` | Токен бота установки в виде `<id бота>:<секрет>`, как его выдаёт `@BotFather` | пусто: бота установки нет |
| `BROOD_TELEGRAM_API` | Адрес Bot API: HTTPS-origin без пути, или HTTP на loopback-адресе | `https://api.telegram.org` |

Остальные настройки сервера описаны в [DEPLOY.md](DEPLOY.md), обращение
с секретами — в [SECRETS.md](SECRETS.md).

## Привязка чата

Привязка связывает учётную запись brood с одним личным чатом Telegram.
Делается она на странице «Профиль» панели ([WEB.md](WEB.md)).

1. Откройте в панели «Профиль», раздел Telegram.
2. Если бота установки нет или нужен свой бот, вставьте токен от
   `@BotFather` и сохраните. Сервер проверяет токен запросом `getMe` и
   показывает имя бота.
3. Нажмите «Получить код привязки». Панель покажет одноразовый код и ссылку
   `https://t.me/<бот>?start=<код>`. Код показывается один раз и действует
   15 минут; новый код отменяет прежний.
4. Откройте ссылку в Telegram и нажмите Start, либо отправьте боту
   в личном чате `/start КОД`.
5. Бот ответит `This chat is now linked to your brood account.`, страница
   профиля обновится сама и покажет привязанный чат.

Ответы бота при неудаче:

| Ответ | Причина |
|---|---|
| `This link code is invalid or has expired. Issue a new code in your brood profile and send it here with /start.` | Код неверен, уже использован или истёк |
| `This chat is linked to another brood account. Unlink it there first.` | Этот чат уже привязан к другой учётной записи |
| `To link this chat, issue a link code in your brood profile and send it here as /start <code>.` | `/start` без кода в непривязанном чате |

На всё остальное в непривязанном чате бот не отвечает.

К учётной записи привязан один чат. Чтобы привязать другой, сначала
отвяжите текущий.

### Отвязка

На странице «Профиль» у пользователя без своего бота есть кнопка
«Отвязать чат». У пользователя со своим ботом вместо неё кнопка «Удалить
бота»: она удаляет токен и отвязывает чат, привязанный через этого бота.
После отвязки сервер не принимает сообщения из чата, а `send to=operator`
из ваших роёв получает отказ.

Привязка также прекращается сама, если Telegram отверг токен бота (401)
или этого бота опрашивает кто-то ещё (409). Причина видна в профиле;
после исправления нужно выдать новый код.

## Написать агенту

Любой текст в привязанном чате, который не начинается с `/`, — сообщение
агенту. Получателя сервер выбирает по порядку:

1. **Ответ на сообщение агента.** Если вы отвечаете (reply) на сообщение,
   которое прислал агент, получатель — этот агент, в каком бы рое он ни
   был.
2. **Имя в начале.** `agent-1: запусти тесты` уходит агенту `agent-1`
   текущего роя; имя сравнивается без учёта регистра, само имя с
   двоеточием в сообщение не попадает.
3. **Единственный агент.** Если в текущем рое работает ровно один агент,
   сообщение уходит ему.

Если работающих агентов несколько и получатель не назван, бот отвечает
`Several agents are running; start the message with "name: " or reply to
an agent's message.` и перечисляет имена. Считаются только работающие
агенты.

Текущий рой — тот, что выбран командой `/use`, а если не выбран —
единственный рой пользователя. Владелец видит свои рои, администратор —
все.

Успешная доставка ничем не подтверждается: бот молчит. Он отвечает только
при неудаче:

| Ответ | Что произошло |
|---|---|
| `agent-1 is not connected.` | Агент не на связи; сообщение не отправлено |
| `agent-1 did not take the message; it was not sent.` | В контейнере нет работающей сессии; сообщение не отправлено |
| `Delivery to agent-1 is unconfirmed; check before sending again.` | Неизвестно, дошло ли сообщение |
| `Swarm main has no running agent.` | В текущем рое никто не работает |
| `You have several swarms; select one with /use NAME.` | Рой не выбран |

Агент получает сообщение так же, как от `bro send`: с пометкой, что оно
от оператора и что отвечать нужно через `send` с `to="operator"`.

### Команды чата

| Команда | Что делает |
|---|---|
| `/swarms` | Перечисляет ваши рои: `Swarms: main, review` |
| `/use NAME` | Делает рой текущим для чата: `Messages now go to swarm main.` Выбор хранится на сервере |
| `/agents` | Перечисляет работающих агентов текущего роя: `Agents of main: agent-1, agent-2` |
| `/help` | Короткая справка; то же отвечает `/start` в уже привязанном чате |

Справка бота:

> Write a message to talk to an agent of your swarm. Reply to an agent's
> message to answer it, or start with "name: " to pick an agent.
> /swarms lists your swarms, /use NAME selects one, /agents lists its agents.

## Как агент пишет владельцу

Агент вызывает инструмент `send` с `to="operator"`. Сообщение приходит
в привязанный чат владельца роя с именем агента в начале:

```
agent-1: Тесты прошли, ветка готова к проверке.
```

Получатель — всегда владелец роя, даже если агенту писал администратор.
Бот берётся свой, а если своего у владельца нет — бот установки.

Агент получает результат доставки: `delivered to the operator's Telegram
chat` или отказ с причиной:

| Причина | Что произошло |
|---|---|
| `the swarm owner has no linked Telegram chat` | Владелец не привязал чат |
| `no Telegram bot is configured for the swarm owner` | Нет ни своего бота, ни бота установки |
| `Telegram did not confirm the message` | Telegram не принял сообщение или не ответил |

## Ограничения

 - **Доставка разовая в обе стороны.** Очереди и повторов нет. Если
   агент не на связи или Telegram недоступен, сообщение не сохраняется:
   отправитель получает отказ и решает сам, повторять ли.
 - **Память об ответах живёт в процессе сервера.** Чтобы ответ (reply)
   попал нужному агенту, сервер помнит, какой агент прислал какое
   сообщение: последние 256 сообщений на чат. После перезапуска сервера
   эта память пуста, и ответ на старое сообщение адресуется как обычный
   текст: по имени в начале или единственному агенту.
 - **Только личные чаты.** Сообщения из групп и каналов, от других ботов
   и от имени, не совпадающего с чатом, бот игнорирует.
 - **Только текст.** Вложения, фотографии и голосовые сообщения агенту не
   передаются.
 - **Длинные сообщения режутся.** Сообщение агента длиннее 4096 символов
   приходит несколькими сообщениями подряд, разрез — по переводу строки
   или пробелу. Ответить можно на любую часть.
 - **Один чат на учётную запись.**

## Приватность и безопасность

 - Токен своего бота только записывается: после сохранения панель и API
   показывают лишь имя бота. Ответы и отказы API токена не содержат.
 - На сервере хранятся: токен и имя своего бота, идентификатор чата и
   пользователя Telegram, имя пользователя Telegram, выбранный рой и
   состояние привязки. Код привязки хранится в виде хэша. Тексты
   сообщений сервер не хранит.
 - Токен лежит в базе сервера как есть, поэтому доступ к файлу базы
   равен доступу к боту.
 - Сообщения проходят через серверы Telegram и видны им. Не передавайте
   агенту через чат секреты; для них есть секреты проекта
   ([SECRETS.md](SECRETS.md)).
 - Сервер принимает сообщение только из чата, привязанного к учётной
   записи, и перед доставкой заново проверяет право пользователя на рой.
   Отключённый пользователь писать агентам не может.
 - Кто получил доступ к вашему чату Telegram, может писать вашим агентам.
   Агенты работают без подтверждения действий, поэтому привязанный чат
   стоит защищать так же, как вход в панель.
